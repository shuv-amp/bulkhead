# Prior work and credits

- **Repository start:** 26 September 2026, during Colosseum Crypto World's Fair (14 Sep – 12 Oct 2026). The Bulkhead design was first drafted on 24 September 2026.
- **Founder's prior work, not included here:** [SP-Differ](https://github.com/shuv-amp/sp-differ), a differential harness for Bitcoin BIP-352 implementations. Bulkhead reuses its *method*, not its code. The method is to compare independent implementations on generated cases and keep every mismatch as a replayable fixture.
- **Credited pattern:** stopping a program by upgrading it to a tiny binary that always fails comes from Dean Little's [`sbpf-asm-abort`](https://github.com/deanmlittle/sbpf-asm-abort).
  - That repository has no license, so none of its files are copied.
  - Bulkhead's abort binaries are generated byte by byte by our own code (`bulkhead_core::floor::ABORT_ELF` and `ABORT_ELF_MINIMAL`).
  - A separate Python builder (`reference/bulkhead_ref.py`) produces the same bytes.
- **Design references:** `docs/14-STATE-OF-THE-ART.md` compares each mechanism with shipped systems (Wormhole NTT, Chainlink CCIP, Kamino, Project 0, MetaMorpho, Lido, Aave) and cites their sources. No code is copied from any of them.
- **Data:**
  - incident facts: Chainalysis, BlockSec, Halborn and Drift;
  - incident statistics: Zhou et al. (IEEE S&P 2023);
  - governance census: solgov's public API (snapshot committed under `evidence/`);
  - market data: DefiLlama.

  Full list: `docs/13-SOURCES.md`.

## Third-party code

No third-party code is copied into this repository. The direct dependencies are all Apache-2.0; the licences of their own dependencies are checked by `cargo-deny` (`deny.toml`, `scripts/deny.sh`):

| Part | Dependencies |
|---|---|
| `bulkhead-core`, `bulkhead-diff` | None |
| Programs (Floor, Vault, Harbor) | [`pinocchio`](https://github.com/anza-xyz/pinocchio) 0.11.2 on-chain; `solana-address` in off-chain builds only |
| Program tests (`programs/tests`) | [`litesvm`](https://github.com/LiteSVM/litesvm) 0.16.0 and the Solana SDK crates |
| Cloud (`cloud/`) | None (Node.js standard library only) |
| Python (`reference/`, `evidence/`, `tools/`) | None (standard library only) |

Test data:
- `tools/testdata/curve25519_vectors.json` is generated by our own test (`programs/tests/tests/curve_vectors.rs`) from `solana-address`'s on-curve check, which uses `curve25519-dalek`.
- The Ed25519 signing test uses RFC 8032 test vector 1.
